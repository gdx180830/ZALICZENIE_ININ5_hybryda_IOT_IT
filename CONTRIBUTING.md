# Zasady współpracy

## Nazewnictwo gałęzi
Nowe gałęzie tworzymy według schematu: `stolica-imie`  
Przykład: `berlin-mateusz`, `paryz-anna`

## Zasady commitów
Każdy commit powinien być opisowy i w języku polskim.  
Przykład: `Dodanie stolicy Berlin - Mateusz Pomagier`

## Pull requesty
- Każdy PR musi zawierać opis wprowadzanych zmian
- PR kierujemy do gałęzi `main` repozytorium prowadzącego
- Przed utworzeniem PR upewnij się że nie ma konfliktów

## Komunikacja
- Pytania i uwagi zgłaszamy przez komentarze w Trello lub Issues na GitHub
- Każdy contributor dodaje siebie do sekcji Autorzy w README.md
